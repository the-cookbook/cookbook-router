# Contracts

Generated contracts connect static route declarations to TypeScript inference. They are generated by `@cookbook/router-cli`, registered through module augmentation, and reflect URLKit-backed parsed URL state.

## Generated files

```sh
cookbook-router generate --routes src/routes.tsx --out-dir .cookbook-router
```

Output:

```txt
.cookbook-router/
  contracts.ts
  register.d.ts
  manifest.json
```

`contracts.ts` contains route-specific interfaces and constants. `register.d.ts` augments `@cookbook/router`. `manifest.json` is a tooling-friendly route list and preserves route-level `url` options such as `arrayFormat`, `invalidSearch`, `invalidHash`, and `unknownSearch` when present.

## Register contracts

`register.d.ts` contains:

```ts
import type { RouterContracts } from './contracts';

declare module '@cookbook/router' {
  interface Register {
    contracts: RouterContracts;
  }
}

export {};
```

Include the generated files in `tsconfig.json`:

```json
{
  "include": ["src", ".cookbook-router/contracts.ts", ".cookbook-router/register.d.ts"]
}
```

After this, app code does not need to import `register.d.ts` manually.

## Route IDs

`RouteId` becomes the union of generated route IDs.

```ts
import type { RouteId } from '@cookbook/router';

const routeId: RouteId = 'blog.articles.show';
```

React links and router methods use `RouteId` for autocomplete.

## Params

Params are generated from path patterns.

```tsx
{
  id: 'users.show',
  path: '/users/{id:int}',
  component: UserPage,
}
```

Generated contract:

```ts
export interface RouteParams {
  'users.show': { id: number };
}
```

URLKit parses built-in numeric constraints. Pass numbers when navigating:

```tsx
<Link to="users.show" params={{ id: 42 }}>
  User
</Link>
```

`{value:range(1,100)}` also generates `number`. Custom constraints such as `{slug:slug}` generate `string` unless URLKit supports typed static inference for that custom constraint.

## Search

Search fields are generated from URLKit-compatible static `search` descriptors.

```tsx
{
  id: 'blog.articles',
  path: '/blog/articles',
  search: {
    query: { value: 'string', optional: true },
    page: { value: 'int', default: 1 },
    filters: { value: 'string', type: 'many', optional: true },
  },
  component: ArticlesPage,
}
```

Generated contract:

```ts
export interface RouteSearch {
  'blog.articles': { query?: string; page: number; filters?: readonly string[] };
}
```

Runtime match state, React hooks, middleware, and lifecycle contexts receive the same URLKit-parsed values.

## Hash

Hash values generate a union.

```tsx
{
  id: 'articles.show',
  path: '/articles/{slug}',
  hash: ['comments', 'share'],
  component: ArticlePage,
}
```

Generated contract:

```ts
export interface RouteHash {
  'articles.show': 'comments' | 'share';
}
```

Routes without hash values generate `never` for the route in `RouteHash`.

## Metadata

Metadata values generate optional fields based on JavaScript `typeof`.

```tsx
meta: {
  title: 'Members',
  requiresAuth: true,
}
```

Generated shape:

```ts
{
  title?: string;
  requiresAuth?: boolean;
}
```

At runtime, metadata is available from normalized routes:

```ts
route.route.route.meta;
```

## Paths

`RoutePaths` maps route IDs to normalized full paths.

```ts
export interface RoutePaths {
  'blog.articles.show': '/blog/articles/{slug:regex([a-z0-9-]+)}';
}
```

Routes without a concrete full path use `never`.

## Outlet context

The generator emits `RouteOutletContext`, but the current generator fills entries with `{}` unless generated contracts are manually refined or extended.

```ts
export interface RouteOutletContext {
  'dashboard.home': {};
}
```

For application-specific context typing, use the generic form:

```tsx
const context = useOutletContext<{ user: User }>();
```

Use route-ID overloads only when the generated or augmented contracts actually include the intended context shape.

## Static extraction requirements

The CLI must be able to statically read route definitions. Keep `id`, `path`, `search`, `hash`, `url`, `children`, slots, redirects, and custom `pathConstraints` in static route declarations. Do not use URLKit runtime builders such as `int().default(1)` in CLI-consumed route files unless the CLI explicitly supports them. Use static descriptors such as `{ value: 'int', default: 1 }` instead.

## Runtime limitations

Generated contracts improve TypeScript inference. They do not replace runtime validation.

- Params are validated and parsed by URLKit-backed path matching/compilation.
- Search and hash descriptors generate TypeScript contracts and URLKit-backed runtime parsed state.
- Metadata shapes come from declared literal values.
- Slot fallback IDs are not generated as route contracts.
- Slot route IDs are generated when they are declared under `layout.slots.<name>.routes`.

## Troubleshooting contracts

### Route IDs are not autocompleting

Check that `.cookbook-router/register.d.ts` is included by `tsconfig.json` and that the editor TypeScript server has reloaded.

### Generated files are stale

Regenerate contracts:

```sh
cookbook-router generate --routes src/routes.tsx --out-dir .cookbook-router
```

### A slot fallback route ID disappeared

That is expected. Slot fallbacks are fallback render definitions, not navigable routes. Use generics for fallback context:

```tsx
const context = useOutletContext<{ user: string }>();
```

### Params are numbers instead of strings

This is expected for built-in numeric constraints. `{id:int}`, `{price:decimal}` and `{value:range}` parse to `number` in generated contracts and runtime state. Custom constraints remain `string` unless URLKit supports typed static inference for them.
